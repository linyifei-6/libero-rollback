# 整体实现缺口分析

基于 **312 条 catalog** 的实测数据（`runs/verify-v13-fixes`，**当时口径**）与运行时能力清单。
按严重程度排序，区分**结构性缺口**（影响结论可信度）与**覆盖缺口**（影响维度完整性）。

> **catalog 已变更（2026-10-16）**：`progress-pulse-*`（24 条）退出，当前 catalog 为 **288 条**；
> 本文中凡引用 312/327/pulse 的数字均为历史测量口径，未改写。当前数字见 `docs/case-matrix-current.md`；退出理由与归档见 `archive/pulse-descoped-20261016/README.md`。
> 缺口 4（机制的窗口覆盖）中 `restore_episode_initial_pose` 当前为 **44 条**（原 68），`displace_from_completed_pose` 仍为 40 条，5 种机制仍只落在 mid 窗口。

## 一、结构性缺口（3 项，影响结论可信度）

### 缺口 1：模型层恢复评测实质为空 —— **最严重**

| 批次 | 有模型恢复评测的用例 |
| --- | ---: |
| v11 原生预检 | **0/327** |
| v12 原生预检 | **0/121** |
| v13 原生预检 | **0/312** |

**全部 312 条都没有经过模型**：原生预检只做"无扰动 baseline + 在真实触发状态试写候选并还原
qpos/qvel"，**不查询策略**。因此当前能回答的只有"注入是否有效合理"，
**无法回答"模型能否发现并修复"**。

仅有的模型证据是归档的 live 批次：
`progress-validation-20261014-v4`（10 条）、`progress-live-20261014-v12`（5 条）、
`progress-validation-20261014`（5 条），合计 **15 次尝试、14 个唯一 case**，占 312 条的 4.5%。

**影响**：数据集的**主要用途是评测模型**，而 95.5% 的用例没有模型证据。
这是最大的缺口，且不能靠预检模式补齐 —— 需要 `--baseline-only` 之外的完整 episode 运行。

### 缺口 2：没有专门的"无操作对照"

| 项 | 现状 |
| --- | --- |
| 保持关系为真的用例 | 54/312（`relation_only` 40 + `relation_holds_control` 14） |
| **完全不写入的对照** | **0 条** |

矩阵 `plan-common-noop-control` 明确要求："用与失效组同类写入改变可见状态，
**但全部目标关系保持成立**；另有无写入基线；检查'看到变化就报丢进度'的假阳性。"

当前 54 条保持关系的用例**都是写入型**（旋转、界内位移、整对平移），
**缺少"不写入"的纯基线对照**。这会混淆两类假阳性：
- 模型把**可见变化**误判为丢进度
- 模型**自主漂移**导致的误判

**影响**：无法把假阳性归因到"扰动"还是"模型自身"。**成本很低**（只需 9 个任务的 no-write episode）。

### 缺口 3：位移的时间参考仍是"回合初始位姿"，未实现"已完成位姿"参考

9 种机制中有 **5 种**只落在 mid 窗口，且位移参考未升级：

| 机制 | 参考点 | 用例 |
| --- | --- | ---: |
| `apply_episode_initial_offset` | **回合初始位姿** | 143 |
| `restore_episode_initial_pose` | 回合初始位姿 | 68 |

矩阵第七节"完成位置参考"明确要求：*"边界组新增当前已完成位姿/目标 region 参考，
**不能仅换标签复用初始偏移**"*。

`displace_to_relation_boundary`（16 条）已按 region 边界解析，方向正确，
但**只覆盖了 16/312 条**；其余 211 条位移用例仍是初始位姿参考。

**影响**：多数位移用例的"失效强度"与目标区域的相对距离无关，
而是与初始位姿的固定偏移绑定 —— 矩阵已指出"初始位置偏移不能代替相对目标 region 的越界量"。

## 二、覆盖缺口（4 项，影响维度完整性）

### 缺口 4：5 种机制只覆盖 mid 窗口

| 机制 | early | mid | later | all_done |
| --- | ---: | ---: | ---: | ---: |
| `displace_from_completed_pose` | 0 | 40 | 0 | 0 |
| `displace_to_relation_boundary` | 0 | 16 | 0 | 0 |
| `displace_reference_object` | 0 | 5 | 0 | 0 |
| `translate_relation_pair` | 0 | 5 | 0 | 0 |
| `restore_native_relation_set` | 0 | 0 | 0 | 18 |

矩阵要求："新增空间计划默认先在 **mid、delay=0** 落一组，以隔离失效机制；
**验证通过后再复制到现有 early/later 窗口**。"

**mid 阶段已完成**（机制已验证有效），**early/later 复制尚未进行**，涉及 66 条机制的窗口扩展。

`after` 窗口也几乎空白：312 条中仅 **2 条**。

### 缺口 5：任务 09 几乎无覆盖

| 任务 | 用例 | 机制种类 |
| --- | ---: | ---: |
| 09 | **1** | **1**（仅 `restore_episode_initial_pose`） |

任务 09 是单目标任务（无 s2），按约定不做执行期主集，但**完成边界协议仍未实现** ——
其唯一 1 条用例 status 为 `trigger_not_reached`，需"success 后不终止并继续注入"。

### 缺口 6：`revert_articulation_goal` 只覆盖任务 00

任务 01（关抽屉）、02（关微波炉门）本质也是功能关系，**但当前 articulation 回退只用于任务 00 的 Turnon**。
功能状态维度在 01/02 上缺失。

### 缺口 7：`restore_captured_checkpoint_pose` 机制已实现但零用例

桥接层映射了 `restore_captured_checkpoint_pose → checkpoint`，运行时白名单也接受 `checkpoint`，
**但 catalog 中 0 条用例使用**（早先的 checkpoint 用例按指示删除后未以其他形式补回）。

## 三、未使用的运行时能力（13 项）

运行时提供 **15 种干预**，本数据集只用了 **2 种**（`completed_subgoal_rollback`、`articulation_setback`）：

```
未使用：action_corruption、action_delay、articulation_impulse、contact_friction、
        dynamic_scene_occupancy、force_impulse、future_feasibility、moving_obstacle、
        observation_freeze、obstruction、rigid_body_displace、semantic_goal、sensor_stream
```

**这是设计选择而非缺陷** —— 本数据集的定位是"已完成子任务的回滚"，
上述能力属于其他扰动族（动作层、观测层、动力学层）。
但若目标是"通用的进度失效评测"，这些是现成可用的扩展面。

## 四、按修复成本排序的建议

| 优先 | 缺口 | 影响 | 成本 |
| --- | --- | --- | --- |
| **1** | 无操作对照（缺口 2） | 区分假阳性归因 | 低：9 个 no-write episode |
| **2** | mid → early/later 扩展（缺口 4） | 66 条机制的时间维度 | 低：复制定义 + 重跑 |
| **3** | 模型层评测（缺口 1） | **结论可信度的根本** | **高：312 条完整 episode（约 11 小时）** |
| **4** | 位移参考升级（缺口 3） | 211 条位移用例的失效强度语义 | 中：需扩展机制的参考点 |
| **5** | 01/02 的 articulation 回退（缺口 6） | 功能状态维度完整性 | 中：需新增关节目标定义 |
| **6** | 任务 09 完成边界协议（缺口 5） | 单目标任务覆盖 | 中：需评测器在 success 后继续观察 |

## 五、结论

**注入有效性维度已基本闭合**：241/312 有效（77.2%），剩余拒绝中 39 条穿透、
10 条无合法边界对属真实几何约束，需要在用例构造层逐任务校准，而非引擎缺陷。

**三个真正的结构性缺口**是：
1. **模型层评测为空**（0/312）—— 数据集的主要用途尚未被验证
2. **无 no-write 对照** —— 假阳性无法归因
3. **位移参考未升级到"已完成位姿"** —— 多数位移用例的语义与矩阵要求不一致

其余为覆盖扩展（时间窗口、任务 09、01/02 功能回退），属已知的阶段性安排。
