# P2 姿态机制：实现与实测（完整 6 条）

依据 `docs/case-matrix-current.md` 第六节 P2 的"姿态"分类。矩阵的判断是
**单独旋转不一定使 `In`/`On` 失效**，需分别做"保持关系的对照"与"失效候选"。实测证实了这一点。

## 一、实现

### 桥接层 `src/libero_rollback/runtime.py`

1. **转发姿态参数**：处理器白名单早已含 `orientation_delta_wxyz`
   （`completed_subgoal_rollback.py:57`，在 `:371-378` 应用于目标位姿），但桥接层从不发出该参数。
2. **支持轴角书写**：用例按"绕某轴旋转某角度"描述更自然，新增
   `orientation_axis_angle: {axis: [x,y,z], angle_rad: r}`，桥接层转四元数。
   转换已单测：`[0,0,1]` 90° → `[0.70711,0,0,0.70711]`；180° → `[0,0,0,1]`。
3. 姿态与 articulation 目标互斥（关节回退没有姿态可改），显式报错。
4. 词表新增 `pose` 档位（偏移为零、仅改姿态），模板补 `l2_grid_pose_{early,mid,later}`。

### 用例 `dataset/pose-control`（6 条，编译 6/6）

任务 01（抽屉）、04（篮子）、07（盘子）各两条：偏航 90°（对照）与倾转 60°（失效候选），
均在 **mid、delay=0**，符合矩阵"先在 mid 落一组以隔离机制"的要求。

## 三、四条结论

### 1. 姿态写入能力已打通

4 条注入有效，规则执行，姿态确实写入目标位姿（`actual_orientation_wxyz` 有记录）。

### 2. 同一旋转机制在不同任务上给出相反结果 —— 证实矩阵的判断

同样是"偏航 90°"：**任务 01 关系保持为真，任务 04/07 变为不成立**。
所以纯旋转**不能预设为失效**，必须逐任务实测。这与矩阵第六节"单独旋转不一定使
`In`/`On` 失效"完全一致。

### 3. 请求的旋转量与实际写入的姿态**不是简单对应**

`orientation_delta` 是与**目标位姿**复合的，不是绕当前姿态旋转。例如任务 07 请求
绕 z 轴 90°，实际写入接近 180°（`[-1,0,0,0]`）—— 因为还叠加了该物体初始朝向。
**含义：用例里写"偏航 90°"不等于物体从当前姿态转 90°**，报告与结论需按实际写入姿态陈述，
不能按请求量陈述。

### 4. 倾转的可行性取决于容器几何

| 任务 | 容器 | 60° 倾转 |
| --- | --- | --- |
| 01 抽屉 | 封闭抽屉 | 被拒（穿透） |
| 04 篮子 | 低矮篮筐 | 通过 |
| 07 盘子 | 平面 | 被拒（穿透，推测与盘面接触有关） |

倾转角需要**按任务/容器分别校准**，不能跨任务复用同一角度。
